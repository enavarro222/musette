# Notes for contributors (and coding agents)

- Rust core in `crates/`, app in `app/` (Expo: web, Android and iOS from one code base). Read `docs/architecture.md` first.
- `crates/protocol-cc600`, `route-cc600` and `settings-cc600` are shared with the GPL firmware (OpenCC600): keep them MIT and `no_std` (`route-cc600` allocates only behind its `build` feature). The firmware depends on them by git; they are the only copy of these formats. Never copy code from c606-oss or other GPL sources into this repo.
- Rust or TypeScript: Rust only for what is shared with other Rust code (the firmware, `musette-cli`, the simulated CC600) or must match the device: file formats written for a device, protocols and sessions, the route analysis a device also gets (climbs). Everything else is TypeScript in `app/`, even logic: the app is already one code base for web, Android and iOS, and a TS change reloads on the phone while a Rust one needs a new native build. Reading a ride (FIT records, summary) is TypeScript, for instance.
- The app reaches Rust only through `app/src/lib/core` (`Core`). Rust logic goes in `crates/musette-core`; `musette-wasm` (web) and `musette-ffi` (iOS, Android) only convert types. A new function goes in all three, plus both loaders (`wasm.ts`, `load.native.ts`), then regenerate the native module (`npm --prefix app/modules/musette-native run generate:android`) and commit its `src/`. Prefer calling an existing core function from TS over adding one.
- Devices: one session for every model (`musette_core::Session`, around each driver's sans-IO session). Protocols, UUIDs, timeouts and capabilities are in Rust; TS runs any session (`BleDevice`) and adds only words (labels, groups, messages). Never copy an op code or a UUID into TS (the search profiles in `registry.ts` are checked against the sessions' channels).
- Never acknowledge or delete a ride on a device before it is verified and stored (`app/src/lib/sync.ts`).
- UI: `@expo/ui` universal components (SwiftUI on iOS, Compose on Android, DOM on the web). Platform differences go in `.web.ts(x)` / `.native.ts` files, not in `if (Platform.OS)` spread through screens.
- Before committing: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, and in `app/`: `npm run wasm && npm run check && npm test && npm run build`.
- App tests (vitest) run the app logic against `src/test/fakeCc600.ts`, the simulated CC600 of the Rust core (`driver_cc600::sim`, the firmware's own transfer and settings code), and `src/test/fakeBryton.ts`. Check bytes sent, not only the result: a wasteful protocol still delivers the right file.
- Heavy builds (Gradle, NDK, emulator) can freeze a laptop: limit them (CPU pinning and a memory cap), and do not run the emulator during a build.
- UI strings are French for now.
